🔗 Nhúng JavaScript vào HTML

Đặt thẻ <script> ở đâu, khi nào — quyết định code chạy đúng hay báo lỗi

Tất cả dự án ở trên đều dùng file JS riêng, liên kết vào HTML qua thẻ <script src="..."></script>. Nhưng đặt thẻ này SAI VỊ TRÍ là nguyên nhân phổ biến nhất khiến người mới học thấy lỗi "Cannot read properties of null".

1️⃣ Vì sao vị trí thẻ script quan trọng?

Trình duyệt đọc HTML từ trên xuống dưới, theo thứ tự. Nếu <script> nằm ở đầu trang (trong <head>) và chạy ngay, JS sẽ cố tìm các phần tử HTML CHƯA ĐƯỢC TẠO RA — vì trình duyệt chưa đọc tới phần <body> bên dưới. 

<head>
  <script src="script.js"></script>   // ❌ chạy TRƯỚC khi <body> tồn tại
</head>
<body>
  <button class="check">Check!</button>
</body>

// script.js
document.querySelector('.check').addEventListener(...);
// → Uncaught TypeError: Cannot read properties of null
// vì document.querySelector('.check') trả về null — nút .check chưa tồn tại lúc này!

2️⃣ Cách kinh điển — đặt script ở CUỐI <body>

Đây chính là cách tất cả dự án ở trên (Pig Game, Modal Window, Guess My Number) đang dùng — đặt <script> ngay TRƯỚC thẻ đóng </body>, để lúc đó toàn bộ HTML phía trên đã được trình duyệt đọc và dựng xong. 

<body>
  <header>...</header>
  <main>
    <button class="check">Check!</button>
  </main>

  <!-- Đặt ở đây — SAU khi mọi phần tử HTML đã tồn tại -->
  <script src="script.js"></script>
</body>
</html>
Ví dụ dễ hiểu: giống việc bạn phải xây xong cả căn nhà (HTML) rồi mới lắp công tắc điện và kết nối dây điện (JS) — nếu lắp công tắc trước khi tường được xây, bạn sẽ nối dây vào "khoảng không" chẳng có gì cả.

3️⃣ Cách hiện đại — giữ script trong <head> kèm defer

Cách này ngày càng phổ biến: vẫn để <script> trong <head>, nhưng thêm thuộc tính defer — trình duyệt tải file JS song song lúc đọc HTML, nhưng CHỈ THỰC THI sau khi toàn bộ HTML đã dựng xong. 

<head>
  <script src="script.js" defer></script>   // ✅ tải song song, chạy sau cùng
</head>
<body>
  <button class="check">Check!</button>
</body>
⚡ defer giúp trang tải nhanh hơn: trình duyệt không phải dừng đọc HTML để tải xong JS mới đọc tiếp ✅ Nhiều script defer sẽ chạy đúng theo THỨ TỰ khai báo trong HTML

4️⃣ async — khác defer ở điểm nào? 

<script src="analytics.js" async></script>
Thuộc tính Tải file Thời điểm chạy Thứ tự nhiều script
(không có gì) Dừng đọc HTML để tải Ngay khi tải xong Đúng thứ tự
defer Tải song song, không chặn HTML Sau khi HTML dựng xong Đúng thứ tự
async Tải song song, không chặn HTML Ngay khi tải xong (có thể TRƯỚC khi HTML xong) KHÔNG đảm bảo thứ tự
💡 defer → dùng cho script cần thao tác DOM (như các dự án ở trên) 💡 async → dùng cho script độc lập, không liên quan DOM (vd: Google Analytics, quảng cáo)

📋 Bảng tổng kết — nên chọn cách nào?

Cách đặt Khi nào dùng
Cuối <body>, không thuộc tính Đơn giản, dễ hiểu nhất cho người mới — cách các dự án trong bài này đang dùng
<head> + defer Cách hiện đại, được khuyên dùng trong dự án thực tế — HTML rõ ràng hơn vì mọi thẻ script gom ở đầu file
<head> + async Chỉ dùng cho script không đụng tới DOM (analytics, ads, font loader...)
<head>, không thuộc tính ❌ Tránh — nguyên nhân phổ biến nhất gây lỗi "Cannot read properties of null"
🔗 Liên hệ thực tế: nếu mở lại code của Pig Game, Modal Window hay Guess My Number, bạn sẽ thấy tất cả đều đặt <script src="script.js"></script> ngay trước </body> — đây không phải ngẫu nhiên, mà là quy tắc bắt buộc để document.querySelector(...) luôn tìm thấy đúng phần tử cần thao tác.

Biến (Variables)

Nơi lưu trữ giá trị — như một chiếc hộp có dán nhãn

🔵 let

Khai báo biến có thể thay đổi giá trị sau này. Còn gọi là mutable variable. Là block-scope (chỉ tồn tại trong khối {} chứa nó).

🟢 const

Khai báo biến chỉ gán 1 lần, không thể gán lại. Còn gọi là immutable variable. Nên dùng const mặc định, chỉ chuyển sang let khi chắc chắn giá trị sẽ đổi.

Ví dụ dễ hiểu: hãy tưởng tượng let là một chiếc ly có thể đổ nước khác vào, còn const là một chiếc ly đã được keo dán chặt xuống bàn — không thể thay ly khác, nhưng nếu bên trong là một chiếc hộp (object/array) thì bạn vẫn có thể mở hộp ra và đổi đồ bên trong. 
let age = 25;
age = 26;              // ✅ OK vì dùng let

const PI = 3.14;
PI = 3.14159;          // ❌ Lỗi! const không gán lại được

const dog = { name: "Spot" };
dog.name = "Rex";       // ✅ OK — sửa thuộc tính bên trong object vẫn được
⚠️ var — từ khóa cũ, tránh dùng (function-scope, dễ gây lỗi)
Quy tắc đặt tên biến Ví dụ
Chỉ dùng chữ, số, _, $ — không bắt đầu bằng số myAge, _temp
Phân biệt chữ hoa/thường myName ≠ MyName
Không dùng từ khóa của JS ❌ let, function, for
Quy tắc lowerCamelCase myFirstName

Kiểu dữ liệu & Chuyển đổi kiểu

7 kiểu nguyên thủy, Dynamic typing và cách JS quy đổi qua lại

7 kiểu dữ liệu nguyên thủy (Primitive)

  • number — số nguyên, thập phân
  • string — chuỗi ký tự, đặt trong " " hoặc ' '
  • boolean — true / false
  • undefined — biến đã khai báo nhưng chưa gán giá trị
  • null — không có giá trị (cố ý gán)
  • symbol — ký hiệu duy nhất
  • bigint — số nguyên rất lớn

Object & Dynamic typing

object và array là kiểu tham chiếu (reference), dùng để lưu dữ liệu phức tạp.

JS là ngôn ngữ định kiểu động — bạn không cần khai báo kiểu dữ liệu, JS tự nhận diện dựa vào giá trị được gán. Dùng typeof để kiểm tra kiểu. 

let x = 5;
console.log(typeof x);   // "number"

x = "hello";
console.log(typeof x);   // "string" — cùng 1 biến, đổi kiểu thoải mái!

Chuyển đổi kiểu (Type Conversion) — chủ động

Bạn tự yêu cầu JS đổi kiểu bằng String(), Number(), Boolean().

Chuyển đổi Cú pháp Ví dụ
Số → chuỗi String(n) String(19) // "19"
Boolean → chuỗi String(bool) String(true) // "true"
Chuỗi → số Number(s) Number("18") // 18
Chuỗi → boolean Boolean(s) Boolean("") // false
Mảng → chuỗi String(arr) String([1,2]) // "1,2"

Ép kiểu (Type Coercion) — JS tự làm ngầm

Xảy ra khi một phép toán xử lý 2 giá trị khác kiểu — JS ngầm chuyển đổi để tính được. 

console.log("19" - "13" + "17");
// "19"-"13" → ép về số → 6, sau đó 6 + "17" → nối chuỗi → "617"

console.log(5 + "5");   // "55" (có string → ưu tiên nối chuỗi)
console.log(5 - "2");   // 3   (- * / luôn ép về number)
Ghi nhớ nhanh: phép + ưu tiên nối chuỗi nếu có ít nhất 1 bên là string. Còn - * / luôn ép cả hai về number.

Truthy

Nhóm Toán tử Ý nghĩa

Toán tử logic

&& AND true khi tất cả đều true
|| OR true khi ít nhất 1 giá trị true

Ví dụ nhanh

5 % 2        // 1 (dư 1)
2 ** 3       // 8 (lũy thừa)
4 === "4"    // false (khác kiểu)
4 == "4"     // true (có ép kiểu)
true && false // false
true || false // true

Toán tử 3 ngôi (Ternary) 

const age = 20;
const drink = age >= 18 ? "🍷 wine" : "🥤 water";
console.log(drink);   // "🍷 wine"
Ví dụ dễ hiểu: toán tử 3 ngôi giống một câu hỏi Yes/No siêu ngắn gọn: "điều kiện đúng thì lấy giá trị A, sai thì lấy giá trị B" — viết gọn trong 1 dòng thay vì cả khối if...else.

Cấu trúc điều khiển

if...else, switch...case — để chương trình "ra quyết định"

if...else

Thực thi khối lệnh dựa trên kết quả đúng/sai của một biểu thức. 

if (age >= 18) {
  console.log("Đủ tuổi");
} else {
  console.log("Chưa đủ tuổi");
}

if...else if...else

Khi có nhiều hơn 2 trường hợp, dùng else if để kiểm tra thêm điều kiện. JS xét lần lượt từ trên xuống, gặp điều kiện nào đúng đầu tiên thì chạy khối đó rồi dừng lại — bỏ qua toàn bộ các điều kiện còn lại. 

if (score >= 9) {
  console.log("Xuất sắc");
} else if (score >= 7) {
  console.log("Giỏi");
} else if (score >= 5) {
  console.log("Trung bình");
} else {
  console.log("Cần cố gắng");
}
// score = 8 → in ra "Giỏi", các nhánh sau không được xét nữa
Ví dụ dễ hiểu — else if: giống như một trạm kiểm tra vé xem phim theo độ tuổi: nhân viên hỏi lần lượt "trên 18 tuổi không?" → nếu không mới hỏi tiếp "trên 13 tuổi không?" → cứ thế cho đến khi tìm được đúng mức vé, tìm thấy là dừng lại ngay, không hỏi thêm câu nào nữa.

switch...case

Thay thế chuỗi if/else if dài khi so sánh 1 biến duy nhất với nhiều giá trị cụ thể. Đừng quên break — nếu quên, code sẽ "rơi" xuống case tiếp theo dù đã khớp đúng case đầu (gọi là hiện tượng fall-through)! 

const day = "Tue";

switch (day) {
  case "Mon":
    console.log("Thứ Hai — họp đầu tuần");
    break;
  case "Tue":
  case "Wed":
  case "Thu":
    console.log("Ngày làm việc bình thường");
    break;
  case "Fri":
    console.log("Thứ Sáu — sắp được nghỉ!");
    break;
  case "Sat":
  case "Sun":
    console.log("Cuối tuần 🎉");
    break;
  default:
    console.log("Không phải ngày hợp lệ");
}
// day = "Tue" → in ra "Ngày làm việc bình thường"
// vì "Tue" khớp case "Tue", không có break riêng nên "rơi" tiếp
// xuống dùng chung code của "Wed"/"Thu", rồi mới gặp break và dừng lại
Ví dụ dễ hiểu: if/else giống như hỏi "có phải không?" nhiều lần liên tiếp theo từng điều kiện khác nhau, còn switch giống như một bảng chọn món trong quán ăn — bạn chỉ ra 1 "biến số" (món) và mỗi "case" là 1 lựa chọn khớp với giá trị của nó. Nhiều case xếp liền nhau không có break ở giữa (như "Tue"/"Wed"/"Thu" ở trên) nghĩa là "các ngày này xử lý giống hệt nhau".
💡 Nên chuyển if/else → switch khi chỉ so sánh 1 biến với nhiều giá trị cụ thể

Hàm (Functions)

Đoạn code được đặt tên để tái sử dụng nhiều lần — nguyên tắc DRY

Hàm gồm: tên hàm, tham số (parameters), thân hàm, và có thể trả về giá trị bằng return. Có 3 cách khai báo hàm chính:

1️⃣ Function Declaration

Có thể gọi hàm trước cả khi nó được khai báo (nhờ hoisting). 

function calcAge(birthYear) {
  return 2026 - birthYear;
}
calcAge(2000); // 26

2️⃣ Function Expression

Hàm được gán vào 1 biến — chỉ gọi được sau khi khai báo. 

const calcAge = function(birthYear) {
  return 2026 - birthYear;
};

3️⃣ Arrow Function — cú pháp ngắn gọn với =>

Nếu thân hàm chỉ 1 dòng: không cần {} và return. Không có từ khóa this riêng. 

const calcAge = birthYear => 2026 - birthYear;
calcAge(2000);   // 26 — gọn hơn hẳn!

// nhiều dòng thì cần {} và return
const greet = (name, age) => {
  const status = age >= 18 ? "người lớn" : "trẻ em";
  return `${name} là ${status}`;
};
Ví dụ dễ hiểu: hàm giống một "cái máy xay sinh tố" — bạn bỏ nguyên liệu (tham số) vào, nó xử lý theo công thức có sẵn (thân hàm), rồi đưa ra ly sinh tố (giá trị return). Mỗi lần cần sinh tố, chỉ việc gọi máy chạy lại, không cần làm lại từ đầu.

💡 Nguyên tắc DRY (Don't Repeat Yourself): dùng hàm để tránh viết đi viết lại cùng một đoạn code.

Mảng (Array)

Lưu nhiều giá trị trong 1 biến duy nhất — mỗi phần tử có 1 chỉ mục (index)

Khai báo

const fruits = ["Apple", "Banana"];
// hoặc
const fruits = new Array("Apple", "Banana");

Truy cập phần tử

Chỉ số bắt đầu từ 0. Muốn lấy phần tử thứ k → dùng array[k-1]. 

fruits[0];       // "Apple"
fruits.length;  // 2 (số phần tử)
Ví dụ dễ hiểu: mảng giống một dãy ô tủ đựng đồ được đánh số từ 0. Muốn lấy đồ ở ô số 3, bạn không gõ "ô số 3" mà gõ tủ[2] — vì đếm bắt đầu từ 0!

Các phương thức (method) thường dùng

Tất cả ví dụ dưới đây đều dùng chung mảng gốc: const fruits = ["Apple", "Banana", "Orange"];

.push()

Thêm 1 phần tử vào cuối mảng. Trả về độ dài mới của mảng. 

fruits.push("Mango");
console.log(fruits);
// ["Apple","Banana","Orange","Mango"]
.unshift()

Thêm 1 phần tử vào đầu mảng, các phần tử khác dịch sang phải. 

fruits.unshift("Grape");
console.log(fruits);
// ["Grape","Apple","Banana","Orange"]
.pop()

Xóa phần tử cuối mảng và trả về chính phần tử đó. 

const last = fruits.pop();
console.log(last);      // "Orange"
console.log(fruits);    // ["Apple","Banana"]
.shift()

Xóa phần tử đầu mảng và trả về chính phần tử đó.

const first = fruits.shift();
console.log(first);     // "Apple"
console.log(fruits);    // ["Banana","Orange"]
.indexOf()

Trả về vị trí (index) của phần tử đầu tiên khớp — không phải giá trị true/false. Trả -1 nếu không tìm thấy. 

fruits.indexOf("Banana");  // 1
fruits.indexOf("Mango");   // -1 (không có)
.includes()

Chỉ trả về true/false — có tồn tại hay không, không cho biết ở vị trí nào. So sánh bằng === (strict equal). 

fruits.includes("Banana"); // true
fruits.includes("banana"); // false (phân biệt hoa/thường!)
.map()

Tạo mảng mới cùng độ dài, mỗi phần tử được biến đổi theo hàm truyền vào. 

const numbers = [1, 2, 3, 4];
const doubled = numbers.map(n => n * 2);
console.log(doubled);   // [2,4,6,8]
.filter()

Trả về mảng mới chỉ chứa các phần tử thỏa điều kiện (độ dài có thể ngắn hơn). 

const numbers = [1,2,3,4,5,6];
const even = numbers.filter(n => n % 2 === 0);
console.log(even);      // [2,4,6]
.reduce()

Gộp cả mảng thành 1 giá trị duy nhất (tổng, trung bình, chuỗi ghép...). Tham số thứ 2 là giá trị khởi đầu. 

const numbers = [1,2,3,4];
const sum = numbers.reduce((total,n) => total+n, 0);
console.log(sum);       // 10
.find()

Trả về phần tử đầu tiên thỏa điều kiện (không phải mảng). undefined nếu không có. 

const numbers = [5,12,8,20];
const found = numbers.find(n => n > 10);
console.log(found);     // 12 (số đầu tiên > 10)
.forEach()

Duyệt qua từng phần tử để thực hiện hành động — không tạo mảng mới, không có return hữu ích. 

fruits.forEach(fruit => console.log(fruit));
// "Apple" → "Banana" → "Orange" (in từng dòng)
.length

Thuộc tính (không phải hàm, không có dấu ngoặc) trả về số phần tử. 

console.log(fruits.length);  // 3
Ví dụ dễ hiểu — map vs filter vs find: nếu mảng là 1 rổ trái cây, filter giống việc bạn chọn ra những quả chín (giữ nguyên số lượng ít hơn), map giống việc bạn ép nước từng quả — số lượng ly nước bằng đúng số quả ban đầu nhưng mỗi phần tử đã "biến hình", còn find giống việc bạn chỉ cần lấy ra đúng 1 quả đầu tiên nhìn thấy chín — tìm được là dừng, không cần cả rổ.

⚠️ Lưu ý về indexOf & includes

  • indexOf quan tâm đến vị trí (trả về số) → dùng khi cần biết phần tử nằm ở đâu.
  • includes chỉ quan tâm có hay không (trả về boolean) → dùng khi chỉ cần kiểm tra sự tồn tại, không cần vị trí.
  • includes dùng so sánh chặt ===, nên "Apple" và "apple" được coi là 2 giá trị khác nhau.

⚠️ Lưu ý chung về mảng

  • map(), filter(), reduce(), forEach() đều bắt buộc tham số truyền vào là 1 hàm (callback) — dùng arrow function () => {} hoặc function(){}, không được truyền thẳng 1 biểu thức toán học.
  • Mảng không phải là kiểu dữ liệu nguyên thủy (primitive) — nó là kiểu tham chiếu (object).
  • Khai báo mảng bằng const vẫn có thể push/pop/sửa phần tử bên trong — chỉ không thể gán lại cả biến bằng một mảng khác. 
const nums = [1, 2, 3];
nums.push(4);        // ✅ OK — [1,2,3,4], vẫn là mảng đó, chỉ đổi nội dung
nums = [9, 9];   // ❌ Lỗi! không được gán lại cả biến const

Vòng lặp (Loops)

Lặp lại code tự động, thay vì chép tay nhiều lần
Vì sao cần vòng lặp? Không dùng vòng lặp: console.log(1); console.log(2); console.log(3); — muốn lặp 100 lần thì chép tay 100 dòng. Dùng vòng lặp for: chỉ 3 dòng code, lặp bao nhiêu lần cũng được.

1️⃣ Vòng lặp for — biết trước số lần lặp 

for (let i = 0; i < 5; i++) {
  console.log(i);
}
// 0  1  2  3  4
Thành phần Vai trò
let i = 0 — khởi tạo Chạy 1 lần duy nhất, trước khi vòng lặp bắt đầu
i < 5 — điều kiện Kiểm tra TRƯỚC mỗi vòng, còn true thì tiếp tục lặp
i++ — cập nhật Chạy SAU mỗi vòng, thường dùng để tăng biến đếm

2️⃣ Duyệt mảng & object — for...of / for...in

for...of — duyệt MẢNG

const fruits = ["Apple", "Mango"];
for (const fruit of fruits) {
  console.log(fruit);
}
// Apple, Mango

Lấy trực tiếp GIÁ TRỊ từng phần tử, không cần chỉ số i.

for...in — duyệt OBJECT

const country = { name: "VN", pop: 100 };
for (const key in country) {
  console.log(key);
}
// name, pop

Lấy TÊN thuộc tính (key), muốn lấy giá trị phải viết country[key].

3️⃣ while & do...while — chưa biết trước số lần lặp 

let count = 0;
while (count < 5) {
  console.log(count);
  count++;   // BẮT BUỘC! quên dòng này → lặp vô hạn
}
⚠️ Cảnh báo: nếu quên count++, điều kiện count < 5 luôn đúng mãi mãi → vòng lặp chạy VÔ HẠN, treo trình duyệt. Luôn phải có 1 dòng thay đổi biến điều kiện bên trong vòng lặp. 
// Ví dụ thực tế: không biết trước bao nhiêu năm,
// chỉ biết "dừng khi dân số >= 110"
let population = 100.3;
let years = 0;
while (population < 110) {
  population += 1;
  years++;
}
console.log(`Sau ${years} năm, đạt ${population} triệu.`);
// Sau 10 năm, đạt 110.3 triệu.

4 tình huống hay dùng while nhất

1. Chờ người dùng nhập đúng dữ liệu

Không biết họ sẽ nhập sai bao nhiêu lần trước khi đúng. 

let age = Number(prompt("Nhập tuổi (1-100):"));
while (age < 1 || age > 100) {
  age = Number(prompt("Sai rồi, nhập lại:"));
}

2. Xử lý cho tới khi đạt 1 ngưỡng

Ví dụ: gửi tiết kiệm, tính bao nhiêu năm mới đạt mục tiêu. 

let saving = 1000, year = 0;
while (saving < 2000) {
  saving = saving * 1.1;  // lãi 10%/năm
  year++;
}
// Sau 8 năm, đủ 2144

3. Đọc dữ liệu tới khi hết

Không biết trước tổng số phần tử, chỉ biết khi nào là hết. 

const queue = ["task1", "task2", "task3"];
while (queue.length > 0) {
  const task = queue.shift(); // lấy & xoá đầu
  console.log(`Đang xử lý: ${task}`);
}

4. Vòng lặp chính của game

Chạy tới khi thua/thoát — không biết trước chơi bao nhiêu lượt. 

let health = 100, turn = 0;
while (health > 0) {
  health -= 10;  // mỗi lượt mất 10 máu
  turn++;
}
console.log("Game Over");
// do...while — chạy TRƯỚC, kiểm tra điều kiện SAU
let x = 99;
do {
  console.log("chạy 1 lần");
} while (x < 5);
// vẫn in ra 1 lần dù x=99 không thoả điều kiện ngay từ đầu
Ví dụ dễ hiểu: while giống việc "nhìn trước khi bước" — kiểm tra đường có an toàn không rồi mới đi. do...while giống "bước rồi mới nhìn" — luôn bước 1 bước đầu tiên, sau đó mới kiểm tra có nên bước tiếp không.
Loại vòng lặp Khi nào dùng
for Biết trước chính xác số lần lặp
for...of Duyệt qua từng phần tử của mảng
for...in Duyệt qua từng thuộc tính (key) của object
while Không biết trước số lần, chỉ biết điều kiện dừng
do...while Giống while, nhưng cần chạy ít nhất 1 lần

4️⃣ break & continue

break — dừng HẲN vòng lặp

for (let i = 0; i < 5; i++) {
  if (i === 2) break;
  console.log(i);
}
// 0  1  (dừng ngay khi i=2)

continue — bỏ qua vòng HIỆN TẠI

for (let i = 0; i < 5; i++) {
  if (i === 2) continue;
  console.log(i);
}
// 0 1 3 4 (bỏ qua i=2, vẫn chạy tiếp)

5️⃣ Vòng lặp lồng nhau (Nested loop) 

for (let i = 1; i <= 3; i++) {      // vòng NGOÀI
  console.log(`Bài ${i}`);
  for (let j = 1; j <= 2; j++) {    // vòng TRONG
    console.log(`  Câu ${j}`);
  }
}
// Bài 1 → Câu 1, Câu 2
// Bài 2 → Câu 1, Câu 2
// Bài 3 → Câu 1, Câu 2   (3 × 2 = 6 dòng)
💡 Vòng trong chạy HẾT mỗi khi vòng ngoài chạy 1 lần ⚠️ Đặt tên biến đếm khác nhau (i, j) để tránh nhầm lẫn khi lồng nhau

6️⃣ Ví dụ thực tế — vòng lặp + tính toán mới

Tip calculator: với mỗi hoá đơn, tính tiền tip rồi cộng ra tổng — lưu cả 2 kết quả vào 2 mảng riêng, trong CÙNG 1 lần lặp. 

// hàm tính tip: 15% nếu 50-300, còn lại 20%
const calcTip = (bill) =>
  bill >= 50 && bill <= 300 ? bill * 0.15 : bill * 0.2;

const bills = [22, 295, 176, 440, 52];
const tips = [];
const totals = [];

for (let i = 0; i < bills.length; i++) {
  const tip = calcTip(bills[i]);    // tính MỚI
  tips.push(tip);
  totals.push(bills[i] + tip);   // dùng lại tip vừa tính
}
// tips:   [4.4, 44.25, 26.4, 88, 7.8]
// totals: [26.4, 339.25, 202.4, 528, 59.8]
Điểm mấu chốt: mỗi vòng lặp không chỉ "đọc" dữ liệu cũ, mà còn tính ra giá trị hoàn toàn mới (tip) rồi dùng ngay giá trị đó cho phép tính tiếp theo (total) — tất cả trong 1 lần duyệt, không cần lặp lại lần 2.

7️⃣ Ví dụ thực tế — vòng lặp + if để lọc dữ liệu

Có 1 mảng chứa nhiều mảng con (danh sách nước láng giềng). Chỉ in các nước từ vị trí thứ 2 trở đi, và CHỈ với những mảng con có ít nhất 2 phần tử. 

const listOfNeighbours = [
  ['Canada', 'Mexico'],
  ['Spain'],
  ['Norway', 'Sweden', 'Russia']
];

for (let i = 0; i < listOfNeighbours.length; i++) {
  const sub = listOfNeighbours[i];

  if (sub.length >= 2) {          // điều kiện lọc
    for (let j = 1; j < sub.length; j++) {  // bắt đầu từ j=1
      console.log(sub[j]);
    }
  }
}
// Mexico
// Sweden
// Russia   (bỏ qua 'Spain' vì mảng con chỉ có 1 phần tử)
💡 if nằm NGOÀI quyết định có xử lý mảng con này không 💡 vòng for bên trong bắt đầu từ j=1 (không phải 0) để bỏ qua phần tử đầu tiên

8️⃣ Ví dụ thực tế — kiểu "accumulator" (tích lũy)

Thay vì tạo mảng mới, gộp cả mảng lại thành 1 con số duy nhất — đây chính là logic đứng sau reduce(). 

function calcAverage(arr) {
  let sum = 0;              // biến tích lũy, phải dùng let vì bị gán lại
  for (let i = 0; i < arr.length; i++) {
    sum += arr[i];         // cộng dồn từng phần tử
  }
  return sum / arr.length;
}
calcAverage([44, 23, 71]);   // 46
// Từng bước: sum=0 → 44 → 67 → 138, rồi 138/3 = 46
Liên hệ với reduce(): arr.reduce((total, num) => total + num, 0) chính là đoạn code trên nhưng viết gọn lại — biến sum đóng đúng vai trò total trong reduce.

⚠️ 3 bẫy hay gặp nhất

Lỗi Hậu quả
Off-by-one: dùng <= thay vì < — i <= arr.length Chạy thừa 1 lần, arr[length] không tồn tại → undefined/NaN
Quên cập nhật biến đếm trong while Điều kiện luôn true → vòng lặp VÔ HẠN, treo trình duyệt
Trùng tên biến ở vòng lặp lồng nhau (i cả 2 vòng) Không lỗi cú pháp nhưng dễ nhầm lẫn kết quả

DOM (Document Object Model)

Cầu nối giữa tài liệu HTML và code JS — cách JS "nhìn thấy" và thay đổi trang web
Vì sao cần DOM? HTML viết sẵn là tĩnh — không đổi được sau khi tải. DOM cho JS quyền đọc, sửa, thêm, xoá từng phần tử NGAY TRÊN trang đang chạy, không cần load lại trang. 
<h1 id="title">Xin chào</h1>

document.getElementById("title").textContent = "Chào bạn!";
// Chữ trên trang tự đổi thành "Chào bạn!" — không cần load lại trang

Cấu trúc — DOM là 1 cây phân cấp (tree) 

<html>
  <body>
    <h1>Tiêu đề</h1>
    <p>Đoạn văn</p>
  </body>
</html>

JS nhìn HTML này thành cây:

document
 └── html
      └── body
           ├── h1
           └── p

Mỗi thẻ HTML trở thành 1 node trong cây — JS đi tới từng node để đọc/sửa nó. document là node gốc (root), điểm truy cập đầu tiên của cả cây.

1️⃣ Chọn phần tử

Cách chọn Trả về
document.getElementById("title") 1 phần tử duy nhất theo id
document.getElementsByClassName("nav-item") Danh sách TẤT CẢ phần tử theo class
document.querySelector(".nav-item") Phần tử ĐẦU TIÊN khớp CSS selector bất kỳ
document.querySelectorAll(".nav-item") TẤT CẢ phần tử khớp CSS selector bất kỳ
⭐ Nên dùng querySelector/querySelectorAll — nhận bất kỳ CSS selector nào, giống hệt cách viết trong file .css vd: document.querySelector("#navbar .nav-item:first-child")

querySelector() vs querySelectorAll()

querySelector()

  • Trả về element đầu tiên khớp
  • Trả về null nếu không tìm thấy
  • Kết quả là 1 đối tượng duy nhất
  • Phù hợp khi biết chắc chỉ có 1 element

querySelectorAll()

  • Trả về tất cả element khớp
  • Luôn trả về NodeList (dù rỗng)
  • Kết quả là 1 collection duyệt được bằng forEach/for
  • Phù hợp khi cần thao tác với nhiều element
📝 Mini Challenge: Viết code để chọn tất cả button có class "action-btn" và thay đổi text của chúng thành "Click me!" 
document.querySelectorAll(".action-btn").forEach(btn => {
  btn.textContent = "Click me!";
});

6️⃣ Sự kiện — addEventListener

Trình duyệt luôn "lắng nghe" hành động của người dùng thông qua Event Loop. Khi sự kiện xảy ra (click, scroll, keypress...), hệ thống sẽ kích hoạt hàm xử lý tương ứng đã đăng ký. 

const button = document.querySelector("button");
button.addEventListener("click", function () {
  console.log("Đã click!");
});

Cú pháp cơ bản — 3 tham số

element

Phần tử DOM cần gắn sự kiện

event

Loại sự kiện dạng chuỗi: 'click', 'mouseover', 'keydown'...

callback

Hàm được gọi khi sự kiện xảy ra

Quy trình 3 bước xử lý sự kiện

Bước Việc cần làm
1. Lựa chọn Element Truy cập DOM để tìm phần tử cần theo dõi (querySelector...)
2. Thêm Event Listener Gắn hàm xử lý sự kiện bằng addEventListener
3. Xử lý Logic Viết code phản hồi: đổi UI, gọi API, cập nhật dữ liệu...

btn.addEventListener("click", () => {

✅ Best Practices khi viết code DOM

📦 Cache DOM Queries

Lưu kết quả query vào biến thay vì truy vấn nhiều lần — đã học ở phần Refactoring bên dưới.

🔒 Null Checks

Luôn kiểm tra element có tồn tại trước khi thao tác — tránh lỗi Cannot read properties of null. 

const btn = document.querySelector(".save");
if (btn) {
  btn.addEventListener("click", handleSave);
}

⚡ Event Delegation

Thêm listener vào phần tử CHA thay vì gắn riêng cho từng phần tử con — đặc biệt hữu ích khi các phần tử con được tạo động (createElement) sau này. 

// Thay vì gắn listener cho từng <li>
// gắn 1 lần duy nhất vào <ul> cha
document.querySelector("ul").addEventListener("click", (e) => {
  if (e.target.tagName === "LI") {
    console.log("Đã click:", e.target.textContent);
  }
});

🧩 Separation of Concerns

Giữ JavaScript, HTML và CSS riêng biệt — JS xử lý logic, HTML là cấu trúc, CSS là giao diện. Tránh viết style trực tiếp qua JS khi có thể dùng classList.

Event Object — tham số "e" chứa gì?

Mỗi khi callback chạy, trình duyệt tự động truyền vào 1 object chứa toàn bộ thông tin về sự kiện vừa xảy ra.

Thuộc tính / phương thức Ý nghĩa
e.target Phần tử THỰC SỰ bị tác động (vd: đúng cái <li> vừa bấm)
e.currentTarget Phần tử đang GẮN listener (vd: <ul> cha nếu dùng event delegation)
e.type Tên loại sự kiện, vd "click"
e.key Phím vừa nhấn (chỉ có ở sự kiện bàn phím)
e.preventDefault() Ngăn hành vi mặc định của trình duyệt
e.stopPropagation() Dừng sự kiện lan truyền lên các phần tử cha

preventDefault() — ngăn hành vi mặc định

Nhiều thẻ HTML có hành vi mặc định khi tương tác — form tự reload trang khi submit, link <a> tự chuyển trang. Muốn tự xử lý bằng JS thay vì để trình duyệt làm mặc định, gọi e.preventDefault(). 

form.addEventListener("submit", function (e) {
  e.preventDefault();   // chặn form tự reload trang
  console.log("Đã submit, xử lý bằng JS!");
});

Event Bubbling & Capturing — sự kiện "lan truyền"

Khi click vào 1 phần tử con, sự kiện không dừng lại ở đó — nó tiếp tục "nổi bọt" (bubble) lên từng phần tử cha, ông, tổ tiên... cho tới document. Đây chính là cơ chế đứng sau Event Delegation đã học ở trên. 

<div id="outer">
  <button id="inner">Click tôi</button>
</div>

document.getElementById("outer").addEventListener("click", () => {
  console.log("outer nghe được!");
});
document.getElementById("inner").addEventListener("click", () => {
  console.log("inner nghe được!");
});
// Click vào button → in ra CẢ 2 dòng, theo thứ tự inner → outer
// (sự kiện "nổi bọt" từ trong ra ngoài)
🛑 Muốn chặn lan truyền lên cha → gọi e.stopPropagation() trong callback của phần tử con 🔗 Event Delegation hoạt động được chính nhờ cơ chế bubbling này
Ví dụ dễ hiểu: event bubbling giống việc bạn hét lên trong 1 căn phòng nhỏ (phần tử con) — âm thanh không chỉ dừng ở phòng đó mà còn vọng ra hành lang (phần tử cha), rồi ra tới sân nhà (document). Muốn "cách âm" để tiếng hét không vọng ra ngoài, gọi stopPropagation().

🧹 Refactoring khi làm việc với DOM (tối ưu code)

Refactoring là kỹ thuật tối ưu lại code, loại bỏ phần trùng lặp — tuân thủ nguyên tắc DRY (Don't Repeat Yourself).

1️⃣ Tránh lặp querySelector nhiều lần

❌ Trước — gọi lại nhiều lần

document.querySelector(".box")
  .classList.add("active");

document.querySelector(".box")
  .style.color = "red";

document.querySelector(".box")
  .textContent = "Đã cập nhật";
// → JS phải tìm lại phần tử trong DOM
//   tận 3 lần cho cùng 1 phần tử!

✅ Sau — lưu vào biến, tái sử dụng

const box = document.querySelector(".box");

box.classList.add("active");
box.style.color = "red";
box.textContent = "Đã cập nhật";
// → chỉ tìm 1 lần, dùng lại biến "box"
//   code ngắn hơn, đỡ tốn tài nguyên

2️⃣ Tách logic lặp lại thành hàm riêng

❌ Trước — code trùng lặp ở 2 nút

btnSave.addEventListener("click", () => {
  message.textContent = "Đã lưu!";
  message.classList.add("show");
  setTimeout(() =>
    message.classList.remove("show"), 2000);
});

btnDelete.addEventListener("click", () => {
  message.textContent = "Đã xoá!";
  message.classList.add("show");
  setTimeout(() =>
    message.classList.remove("show"), 2000);
});

✅ Sau — gộp thành 1 hàm dùng chung

function showMessage(text) {
  message.textContent = text;
  message.classList.add("show");
  setTimeout(() =>
    message.classList.remove("show"), 2000);
}

btnSave.addEventListener("click",
  () => showMessage("Đã lưu!"));
btnDelete.addEventListener("click",
  () => showMessage("Đã xoá!"));
// → cần đổi thời gian hiện (2000ms)? chỉ sửa 1 chỗ
Ví dụ dễ hiểu: không refactor giống việc bạn ghi cùng 1 công thức nấu ăn ra giấy nhớ dán khắp bếp — muốn đổi 1 nguyên liệu phải sửa từng tờ. Refactor giống việc gom công thức đó vào đúng 1 cuốn sổ tay (hàm dùng chung) — cần sửa gì chỉ mở đúng 1 trang.

3️⃣ So sánh Bad Code vs Good Code

❌ Bad Code (Lặp lại)

function updateHeader1() {
  document.getElementById('header1')
    .style.color = 'red';
  document.getElementById('header1')
    .style.fontSize = '24px';
}

function updateHeader2() {
  document.getElementById('header2')
    .style.color = 'red';
  document.getElementById('header2')
    .style.fontSize = '24px';
}
// ...lặp lại y hệt cho header3, header4...

✅ Good Code (DRY)

function updateHeader(elementId) {
  const header = document.getElementById(elementId);
  header.style.color = 'red';
  header.style.fontSize = '24px';
}

// Sử dụng
updateHeader('header1');
updateHeader('header2');
updateHeader('header3');
Điểm khác biệt: Good code chỉ viết logic MỘT LẦN, tái sử dụng bằng tham số. Khi cần thay đổi, chỉ sửa 1 chỗ thay vì cả ba.

Tái cấu trúc mã nguồn — cách triển khai DRY

Bước Việc cần làm

2. Tách logic chung Tạo hàm, class hoặc module chứa phần logic được dùng nhiều lần

⚠️ Quy tắc quan trọng: sau mỗi lần refactor, LUÔN chạy lại chương trình để chắc chắn kết quả không đổi — nếu đổi, đó không còn là refactor thuần tuý nữa

8️⃣ RegExp — kiểm tra định dạng dữ liệu người dùng nhập

RegExp (Regular Expression / biểu thức chính quy) là 1 "khuôn mẫu" mô tả định dạng chuỗi — cực kỳ hữu ích khi validate dữ liệu lấy từ DOM (email, số điện thoại, mật khẩu...) trước khi xử lý tiếp. 

// Tạo RegExp — 2 cách viết tương đương
const pattern1 = /hello/i;              // literal — hay dùng nhất
const pattern2 = new RegExp("hello", "i");  // constructor — khi pattern là biến động

// Áp dụng vào 1 input lấy từ DOM
const email = document.querySelector(".email").value;
const emailPattern = /^[\w.-]+@[\w-]+\.[a-z]{2,}$/i;

if (emailPattern.test(email)) {
  console.log("Email hợp lệ ✅");
} else {
  console.log("Email sai định dạng ❌");
}

Flags (cờ) — đặt sau dấu / cuối

g Global — tìm tất cả, không dừng ở kết quả đầu tiên
i Ignore case — không phân biệt hoa/thường
m Multiline — ^ $ khớp từng dòng thay vì cả chuỗi
s Dotall — cho . khớp cả ký tự xuống dòng

Character class — nhóm ký tự hay dùng

\d / \D 1 chữ số (0-9) / KHÔNG phải chữ số
\w / \W 1 ký tự chữ/số/gạch dưới / ngược lại
\s / \S 1 khoảng trắng / KHÔNG phải khoảng trắng
. Bất kỳ 1 ký tự nào (trừ xuống dòng)
Cú pháp Ý nghĩa
[abc] / [^abc] 1 ký tự nằm trong / KHÔNG nằm trong tập abc
[a-z] / [0-9] 1 ký tự trong khoảng a→z / 0→9
a|b Khớp a HOẶC b
^ / $ Đầu chuỗi / cuối chuỗi
+ Xuất hiện 1 lần trở lên
* Xuất hiện 0 lần trở lên
? Xuất hiện 0 hoặc 1 lần (tuỳ chọn)
{n} / {n,m} Đúng n lần / từ n đến m lần
(x) Nhóm bắt (capturing group) — dùng lại được kết quả
Giải mã pattern email ở trên: ^[\w.-]+ = phần tên bắt đầu chuỗi, gồm chữ/số/chấm/gạch ngang, ít nhất 1 ký tự · @ = bắt buộc có ký tự @ · [\w-]+ = tên miền · \.[a-z]{2,}$ = dấu chấm + đuôi domain ít nhất 2 chữ cái, kết thúc chuỗi.

Các phương thức RegExp hay dùng với DOM

Phương thức Ý nghĩa
regex.test(str) Trả về true/false — chuỗi có khớp pattern không
str.match(regex) Trả về mảng các đoạn khớp được, hoặc null nếu không có
str.replace(regex, "x") Thay thế đoạn khớp bằng chuỗi khác
str.split(regex) Tách chuỗi thành mảng dựa theo pattern

Attribute vs Property

2 khái niệm rất dễ nhầm khi làm việc với DOM trong JavaScript

🏷️ Attribute (thuộc tính HTML)

Là giá trị được khai báo ngay trong markup HTML. Luôn luôn là chuỗi (string), đại diện cho giá trị ban đầu lúc trang tải — gần như không đổi trừ khi bạn chủ động sửa bằng setAttribute().

⚙️ Property (thuộc tính DOM)

Là thuộc tính của object JS đại diện cho phần tử đó trong DOM. Phản ánh trạng thái HIỆN TẠI, sống động — có thể là bất kỳ kiểu dữ liệu nào (string, boolean, number, function...), thay đổi liên tục khi người dùng tương tác.

Ví dụ dễ hiểu: attribute giống ngày sinh ghi trên giấy khai sinh — cố định, không đổi theo thời gian. Property giống tuổi thực tế của bạn hôm nay — luôn cập nhật theo thời gian thực, dù vẫn "bắt nguồn" từ ngày sinh ban đầu đó.

Ví dụ thực chiến — ô input 

<input id="box" value="Hello">

const el = document.getElementById("box");

// Ngay sau khi tải trang, cả 2 đều giống nhau:
el.getAttribute("value");  // "Hello"
el.value;                 // "Hello"

// Người dùng gõ thêm chữ " World" vào ô input...
el.getAttribute("value");  // "Hello"  ← KHÔNG đổi, vẫn là giá trị HTML gốc
el.value;                 // "Hello World"  ← property phản ánh đúng nội dung hiện tại

Ví dụ 2 — checkbox

<input type="checkbox" checked>

el.getAttribute("checked"); // "" (có mặt = true ban đầu)
el.checked;  // true

// User bỏ tick checkbox...
el.getAttribute("checked"); // vẫn còn "" — không đổi!
el.checked;  // false — đúng trạng thái hiện tại

Ví dụ 3 — class

<div class="box active"></div>

el.getAttribute("class"); // "box active" (chuỗi)
el.className;   // "box active" (chuỗi, property tương ứng)
el.classList;   // object đặc biệt: .add() .remove() .toggle()

Bảng so sánh nhanh

Attribute Property
Nơi định nghĩa Trong mã HTML (markup) Trên object JS đại diện phần tử DOM
Kiểu dữ liệu Luôn là string Bất kỳ kiểu nào (string, boolean, number...)
Giá trị phản ánh Trạng thái BAN ĐẦU lúc tải trang Trạng thái HIỆN TẠI, thời gian thực
Cách truy cập getAttribute() / setAttribute() Truy cập trực tiếp element.tenProperty
Đồng bộ 2 chiều? Hầu hết được "reflect" (đồng bộ) lúc đầu, nhưng 1 số cặp (value, checked...) sẽ TÁCH RA khi người dùng tương tác
✅ Muốn biết/đổi trạng thái HIỆN TẠI (giá trị đang gõ, có đang tick không...) → dùng Property ✅ Muốn đọc/ghi giá trị GỐC khai báo trong HTML, hoặc custom data-* → dùng Attribute (getAttribute/setAttribute/dataset) 💡 data-* attribute tuỳ chỉnh luôn truy cập qua property đặc biệt element.dataset.tenKhoa

🎲 Dự án thực hành: Pig Game

Áp dụng toàn bộ kiến thức DOM + state variables + event listener vào 1 game hoàn chỉnh

Luật chơi

🎲 Roll dice

Tung xúc xắc → ra số khác 1 → cộng dồn vào điểm tạm (current score). Ra đúng số 1 → mất điểm tạm, đổi lượt ngay.

✋ Hold score

Chốt điểm tạm vào tổng điểm. Nếu tổng điểm ≥ 100 → thắng. Nếu chưa → đổi lượt cho đối thủ.

🔄 Reset game: đặt lại toàn bộ điểm về 0, Player 1 chơi trước

1️⃣ Chọn phần tử & khai báo state

Mọi nút bấm đều cần "nhìn thấy" cùng 1 bộ biến trạng thái — nên khai báo ở phạm vi NGOÀI CÙNG, không khai báo riêng bên trong từng hàm. 

const player0El = document.querySelector('.player--0');
const player1El = document.querySelector('.player--1');
const score0El = document.getElementById('score--0');
const score1El = document.getElementById('score--1');
const diceEl = document.querySelector('.dice');
const btnRoll = document.querySelector('.btn--roll');
const btnHold = document.querySelector('.btn--hold');
const btnNew = document.querySelector('.btn--new');

// state — khai báo NGOÀI CÙNG bằng let, để mọi hàm dùng chung
let scores, currentScore, activePlayer, playing;
⚠️ Bẫy hay gặp nhất của bài này: nếu khai báo const scores = [0,0] BÊN TRONG hàm init(), biến này chỉ tồn tại cục bộ trong hàm đó — các hàm khác (như xử lý nút Hold) sẽ báo lỗi scores is not defined vì không "nhìn thấy" nó.

2️⃣ init() — hàm khởi tạo / reset 

const init = function () {
  scores = [0, 0];   // KHÔNG dùng const, chỉ GÁN LẠI biến ngoài
  currentScore = 0;
  activePlayer = 0;
  playing = true;

  score0El.textContent = 0;
  score1El.textContent = 0;
  diceEl.classList.add('hidden');
};

init();   // gọi 1 lần khi trang vừa load
💡 Viết thành hàm riêng để dùng lại cho cả lúc load trang LẪN lúc bấm nút "New Game" — đúng tinh thần refactoring

3️⃣ switchPlayer() — hàm đổi lượt dùng chung 

const switchPlayer = function () {
  document.getElementById(`current--${activePlayer}`).textContent = 0;
  currentScore = 0;
  activePlayer = activePlayer === 0 ? 1 : 0;
  player0El.classList.toggle('player--active');
  player1El.classList.toggle('player--active');
};
Bước Việc cần làm khi đổi lượt
1 Reset hiển thị điểm tạm về 0
2 Reset biến currentScore — quên bước này thì điểm tạm cũ bị "dính" sang lượt sau
3 Đảo activePlayer giữa 0 và 1
4 Toggle class đổi màu nền cho cả 2 người chơi
⚠️ classList.toggle() không tự đổi màu: classList chỉ thêm/bớt TÊN class — muốn thấy đổi màu nền, CSS phải có sẵn rule cho class đó, ví dụ .player--active { background-color: #2f2f2f; }

4️⃣ Event: nút Roll — tung xúc xắc 

btnRoll.addEventListener('click', function () {
  if (playing) {
    const dice = Math.trunc(Math.random() * 6) + 1;
    diceEl.classList.remove('hidden');
    diceEl.src = `dice-${dice}.png`;

    if (dice !== 1) {
      currentScore += dice;
      document.getElementById(`current--${activePlayer}`).textContent = currentScore;
    } else {
      switchPlayer();
    }
  }
});
⚠️ classList.remove('.hidden') — thừa dấu chấm: classList làm việc với tên class THUẦN TÚY, không cần dấu . ở đầu (dấu chấm chỉ dùng trong CSS selector của querySelector). Viết '.hidden' sẽ không báo lỗi nhưng cũng không có tác dụng gì.

5️⃣ Event: nút Hold — giữ điểm 

btnHold.addEventListener('click', function () {
  if (playing) {
    scores[activePlayer] += currentScore;
    document.getElementById(`score--${activePlayer}`).textContent = scores[activePlayer];

    if (scores[activePlayer] >= 100) {
      playing = false;
      diceEl.classList.add('hidden');
    } else {
      switchPlayer();
    }
  }
});

btnNew.addEventListener('click', init);
⚠️ addEventListener('click', init()) — thừa dấu ngoặc: có () sau init khiến hàm CHẠY NGAY khi dòng này thực thi (lúc trang load), thay vì đợi tới lúc click. Luôn truyền TÊN hàm, không kèm dấu ngoặc.

🪟 Dự án thực hành: Modal Window

Cửa sổ pop-up kinh điển — bài tập DOM ngắn gọn nhưng hội tụ rất nhiều kỹ thuật hay dùng

Modal là 1 hộp thoại nổi lên giữa màn hình (vd: form đăng ký, thông báo, xác nhận xoá...), kèm 1 lớp phủ mờ (overlay) phía sau để làm mờ nội dung trang và ngăn thao tác ngoài modal.

1️⃣ Chọn phần tử 

'use strict';

const modal = document.querySelector('.modal');
const overlay = document.querySelector('.overlay');
const btnCloseModal = document.querySelector('.close-modal');
const btnsOpenModal = document.querySelectorAll('.show-modal');
💡 'use strict' — bật chế độ nghiêm ngặt, giúp JS báo lỗi rõ ràng hơn (vd: gán giá trị cho biến chưa khai báo) ⚠️ btnsOpenModal có "s" — vì querySelectorAll trả về NHIỀU phần tử (NodeList), khác hẳn 3 biến còn lại chỉ có 1 phần tử

2️⃣ openModal() / closeModal() — cặp hàm đối xứng 

const openModal = function () {
  modal.classList.remove('hidden');
  overlay.classList.remove('hidden');
};

const closeModal = function () {
  modal.classList.add('hidden');
  overlay.classList.add('hidden');
};
Liên hệ: đây chính là kỹ thuật classList.add/remove đã học ở nhánh DOM — ẩn/hiện phần tử không phải bằng cách xoá nó khỏi trang, mà bằng cách toggle 1 class CSS (thường là .hidden { display: none; }).

3️⃣ Nhiều nút mở, 1 nút đóng — vì sao cần vòng lặp?

Trang có thể có NHIỀU nút cùng mở modal (vd: nhiều nút "Đăng ký" rải khắp trang), nhưng addEventListener chỉ gắn được cho 1 phần tử mỗi lần gọi — nên phải lặp qua từng phần tử trong NodeList. 

for (let i = 0; i < btnsOpenModal.length; i++)
  btnsOpenModal[i].addEventListener('click', openModal);
💡 Đây chính là ví dụ thực tế của nhánh Vòng lặp: for + NodeList.length, không biết trước trang có bao nhiêu nút "show-modal"

4️⃣ 3 cách đóng modal — cho trải nghiệm người dùng tốt hơn

Cách 1 — bấm nút X

btnCloseModal.addEventListener(
  'click', closeModal
);

Cách 2 — bấm ra ngoài overlay

overlay.addEventListener(
  'click', closeModal
);

Overlay là lớp phủ mờ toàn màn hình phía sau modal — bấm vào đó nghĩa là người dùng muốn thoát ra. 

// Cách 3 — nhấn phím Escape
document.addEventListener('keydown', function (e) {
  if (e.key === 'Escape' && !modal.classList.contains('hidden')) {
    closeModal();
  }
});
Vì sao cần kiểm tra !modal.classList.contains('hidden')? Nếu không có điều kiện này, người dùng nhấn Escape bất cứ lúc nào — kể cả khi modal đang ẩn — cũng sẽ gọi closeModal() một cách vô nghĩa. Kiểm tra "modal có đang mở không" trước, giống hệt logic if (playing) trong Pig Game — luôn canh gác (guard) trước khi cho hành động xảy ra.

Sự kiện bàn phím Ý nghĩa

e.key Tên phím vừa nhấn, dạng chuỗi — vd "Escape", "Enter", "a"
console.log(e.key) Cách debug kinh điển để xem chính xác tên phím JS nhận diện là gì

📋 Tổng kết — 4 kỹ thuật hội tụ trong bài Modal

1️⃣ classList.add/remove — ẩn hiện qua CSS class, không xoá phần tử khỏi DOM 2️⃣ Vòng lặp qua NodeList — gắn cùng 1 listener cho nhiều phần tử cùng lúc 3️⃣ Nhiều cách kích hoạt cùng 1 hành động — nút X, click overlay, phím Escape đều gọi chung closeModal() 4️⃣ Guard condition — kiểm tra điều kiện trước khi hành động, tránh gọi hàm thừa

🔢 Dự án thực hành: Guess My Number

Game đoán số kinh điển — ráp state, event, kiểu dữ liệu và style qua JS vào 1 sản phẩm

Máy random 1 số bí mật từ 1-20, người chơi có 20 điểm, đoán sai bị trừ điểm, đoán đúng thì thắng và có cơ hội phá kỷ lục (highscore).

1️⃣ State & số bí mật 

const secretNumber = Math.trunc(Math.random() * 20) + 1;
let score = 20;
let highscore = 0;
💡 secretNumber dùng const vì chỉ random 1 LẦN DUY NHẤT lúc load trang, không đổi trong suốt ván chơi 💡 score, highscore dùng let vì bị GÁN LẠI liên tục mỗi lượt đoán

2️⃣ ⚠️ Điểm cần lưu ý — chưa lưu phần tử vào biến

Bài này gọi document.querySelector('.message') lặp lại RẤT NHIỀU LẦN thay vì lưu vào biến 1 lần — đúng cái bẫy đã học ở phần Refactoring (nhánh DOM). Đây là điểm đầu tiên nên sửa nếu muốn code sạch hơn:

❌ Cách bài đang làm

document.querySelector('.message')
  .textContent = 'No number';
document.querySelector('.score')
  .textContent = score;
// lặp lại querySelector ở MỌI nhánh if

✅ Nên refactor thành

const messageEl = document.querySelector('.message');
const scoreEl = document.querySelector('.score');
// khai báo 1 lần ở đầu file, dùng lại khắp nơi
messageEl.textContent = 'No number';
scoreEl.textContent = score;

3️⃣ Kiểm tra input rỗng — toán tử ! với falsy value 

const guess = Number(document.querySelector('.guess').value);

if (!guess) {
  messageEl.textContent = 'No number';
}
Vì sao !guess bắt được ô input rỗng? Nếu người dùng chưa nhập gì, .value trả về chuỗi rỗng "", qua Number("") thành 0. Nhớ lại nhánh Kiểu dữ liệu: 0 là 1 trong 5 giá trị falsy, nên !0 → true → vào đúng nhánh "No number". Nếu người dùng gõ chữ (không phải số), Number("abc") → NaN, mà NaN cũng là falsy → vẫn bắt được lỗi này!

4️⃣ Đổi CSS trực tiếp qua JS khi thắng 

} else if (guess === secretNumber) {
  messageEl.textContent = 'Correct Number!';
  document.querySelector('body').style.backgroundColor = '#60b347';
  document.querySelector('.number').style.width = '30rem';

  if (score > highscore) {
    highscore = score;
    document.querySelector('.highscore').textContent = highscore;
  }
}
💡 .style.backgroundColor — CSS "background-color" viết thành camelCase khi truy cập qua JS (bỏ dấu gạch ngang, viết hoa chữ cái sau) 💡 Đây chính là property đã học ở nhánh Attribute vs Property — .style là 1 object sống, đổi ngay lập tức trên trang

5️⃣ Đoán sai — gộp nhánh Too high / Too low 

} else if (guess !== secretNumber) {
  if (score > 1) {
    messageEl.textContent = guess > secretNumber ? 'Too high!' : 'To Low';
    score--;
    scoreEl.textContent = score;
  } else {
    messageEl.textContent = 'You lost the game!';
    scoreEl.textContent = 0;
  }
}
🐛 Lỗi chính tả thật trong bài — "To Low" thiếu chữ "o": Đúng ra phải là 'Too low!'. Code vẫn CHẠY ĐÚNG (không lỗi cú pháp) vì đây chỉ là chuỗi hiển thị, nhưng người chơi sẽ thấy chữ sai chính tả trên màn hình. Đây là lỗi rất hay gặp: JS không thể tự phát hiện lỗi chính tả trong 1 chuỗi văn bản — phải tự đọc kỹ hoặc test bằng mắt.
🔗 Liên hệ với bài Refactoring đã học: đoạn code comment ở cuối file gốc (2 nhánh else if (guess > secretNumber) và else if (guess < secretNumber) riêng biệt) chính là PHIÊN BẢN CHƯA REFACTOR — gộp lại thành 1 nhánh guess !== secretNumber kèm toán tử 3 ngôi như code hiện tại chính là ví dụ thực chiến của kỹ thuật "gộp điều kiện trùng lặp" đã học.

6️⃣ ⚠️ Tính năng còn thiếu — nút "Again!"

HTML có sẵn <button class="btn again">Again!</button> nhưng file JS chưa có đoạn addEventListener nào gắn cho nút này — game hiện tại chơi xong không có cách nào chơi lại mà không load lại trang. 

// Cần thêm: hàm reset giống init() trong Pig Game
const btnAgain = document.querySelector('.again');

btnAgain.addEventListener('click', function () {
  score = 20;
  // cần biến secretNumber ở scope ngoài (let), rồi random lại
  // secretNumber = Math.trunc(Math.random() * 20) + 1;
  scoreEl.textContent = score;
  messageEl.textContent = 'Start guessing...';
  document.querySelector('.number').textContent = '?';
  document.querySelector('body').style.backgroundColor = '#222';
  document.querySelector('.number').style.width = '15rem';
});
⚠️ Bẫy nếu sửa lại: muốn random lại secretNumber khi bấm "Again!", biến này phải khai báo bằng let thay vì const — giống hệt lưu ý ở Pig Game: biến nào cần đổi giá trị qua nhiều lần chơi thì không thể dùng const.
